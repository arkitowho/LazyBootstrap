# 更新包创建工具

适用于 Windows x64，使用 Python 3.10+ 与 Tkinter。导入 XML 规则的 XPath 1.0 回放依赖 `lxml`。
双击本目录的 `start.bat`，或运行 `python Tools/Update-Package-Tool/main.py`。
Python 安装程序中需要启用 Tcl/Tk；本目录依赖上一级的 `generate_update_checksums.py`，不要单独搬走。

首次使用导入功能前，在仓库根目录安装依赖：

```text
python -m pip install -r Tools/Update-Package-Tool/requirements.txt
```

程序不会自动联网安装；缺少 `lxml` 时会显示中文安装提示。XPath 使用方式参考 [lxml 官方说明](https://lxml.de/xpathxslt.html)。

## 使用

1. 选择**已解压的原始游戏增量目录**和已存在的输出位置。原始目录可直接含 `data`、`modules`、`prop` 等内容，也可外套 `contents`。无法唯一识别时，在“内容根目录”中选择真正的游戏内容目录；所有选中内容都会被复制，不执行包内脚本。
2. 填写旧、新版本，如 `2026071400` 和 `2026080500`。10 位版本号由有效日期 `YYYYMMDD` 和两位序号组成。默认名称为 `UPDATE_LAZY_KFC_2026071400 to 2026080500`。填写自定义后缀时，新旧版本可留空；勾选修改版本日期仍必须提供新版本。
3. 根据需要勾选组件及附加规则。所有选项和新建规则默认关闭；未勾选的路径和规则不参与生成。配置只保存在本次会话中，不会在下次启动自动启用。
4. 点击“检查并预览”，查看源目录映射和完整 `update`。确认后点击“生成更新包目录”。输入变化后需要重新预览。
5. 完成后打开输出目录。工具不压缩，压缩时保持整个目录内容完整，文件名沿用 `UPDATE_LAZY_KFC_` 前缀。

输出结构：

```text
UPDATE_LAZY_KFC_2026071400 to 2026080500/
├── update
├── checksums
└── source/
    ├── contents/
    ├── launcher/       # 勾选编译并加入启动器时
    ├── asphyxia/
    │   └── plugins/
    │       └── sdvx@asphyxia/  # 勾选下载 KFC 插件时
    ├── 启动.exe        # 与 launcher 同次编译、一起加入
    └── extras/         # 额外复制规则
```

`update` 和 `checksums` 都是无扩展名 UTF-8 JSON。SHA-256 清单包含所有文件（包括 `update`），只排除根目录的 `checksums` 自身。修改生成内容后需重新生成校验清单。

## 可选组件

- **spice2x**：从官方 `spice2x/spice2x.github.io` GitHub 发布 API 获取最新稳定版；勾选包含预发布时，从最近 100 条公开发布中按发布时间选择最新版本。不获取 nightly。下载普通版 ZIP，仅写入 `source/contents/spice64.exe`，替换原增量包的同名文件。下载版本显示在日志中；校验发布大小和官方提供的 SHA-256。官方未提供摘要时会明确记录，只核对长度。网络错误、限流、下载损坏或资产结构变化都会停止生成，不跳过已选组件。网络单次读取超时为 20 秒。
- **版本日期**：不携带原增量包的 `prop/ea3-ident.xml`，而是在复制后通过 `editXml` 修改 `/ea3_conf/soft/ext`，保留用户其他配置。安装目标必须已有此文件，XPath 必须恰好匹配一项，否则安装预演失败。
- **编译并加入启动器**：一个复选框同时加入 launcher 和启动.exe，无需填写路径。点击“检查并预览”时，从仓库根目录运行 `pwsh -NoProfile -NonInteractive -File build.ps1`，使用脚本既有的 Release / win-x64 / NativeAOT 发布配置。编译成功后，把 `build` 内全部内容映射到包内 `source`，仅在包内将根目录 `Launcher.exe` 重命名为 `启动.exe`；仓库 `build/Launcher.exe` 保留原名。`launcher` 使用 `mirror` 安装，**会移除目标中多余文件**，其他顶层产物使用 `copy`。需要 PowerShell 7、.NET 10 SDK 和 NativeAOT 所需的 Windows C++ 构建环境。
- **asphyxia KFC 插件**：勾选后，生成时从 [22vv0/asphyxia_plugins 的发布资产](https://github.com/22vv0/asphyxia_plugins/releases)下载最新的 `kfc` 开头 ZIP，无需填写本地路径。分页检查公开发布（包含预发布，排除草稿），按资产更新时间选择；时间相同时按发布时间及名称稳定排序，不使用版本号文本排序，也不会误选其他游戏插件。下载后核对长度和发布方提供的 SHA-256，再解压至 `source/asphyxia/plugins/sdvx@asphyxia`。如果全部条目位于同一个顶层目录中，去掉这一层，例如 `asphyxia_plugins-kfc/index.ts` 变为 `sdvx@asphyxia/index.ts`；如果根目录已有文件或存在多个顶层目录，直接保留内容结构。只移除一层，不递归压平内部目录。安装清单仅将该插件目录复制到游戏的 `asphyxia/plugins/sdvx@asphyxia`，不下载或替换 asphyxia 主程序。

插件下载、校验或解压失败会停止打包并清理本次暂存内容，不跳过此选项。解压前检查全部 ZIP 路径，拒绝越界路径、链接、Windows 名称冲突及额外 `update` 清单；解压后再次检查与附加规则的文件类型冲突。插件文件全部计入最终 `checksums`。没有发布方摘要时会明确记录，只核对下载长度。
编译输出实时显示在日志中；生成阶段使用预览时本次编译的产物，并检查产物没有变化，不重复编译。重新预览会重新执行脚本。脚本会重建仓库 `build` / `build_tmp`，因此所选输入、组件和输出不能位于这些目录内。取消会结束本次编译进程树；编译失败、取消、缺少必要产物或预览后产物变化时均停止，不退回旧产物继续打包。取消可能在仓库留下部分编译产物，下次预览会由脚本重新构建。

## 附加规则

点击“添加复制／删除”填写规则，或点击“添加 XML 规则”打开可视化编辑器，再手动勾选启用，或在列表“启用”列切换。目标路径相对于游戏根目录，例如 `contents/data_mods/_cache`；复制目录会递归合并，保留目标独有文件。可以调整列表顺序。

### XML 可视化编辑

1. 点击“选择参考 XML”。文件在后台读取，左侧树按展开需要加载；同级元素较多时，每页显示 200 项。搜索框按元素名、属性名和属性值、文本搜索，“下一项”在结果间切换。
2. 选择元素，右侧显示文本和属性。选择属性后，下方输入框显示完整属性值，支持长值和多行。可修改文本或属性、添加／删除属性、删除元素，以及添加子元素、在前后插入或替换元素。
3. 添加／替换以元素名、命名空间 URI、文本和属性表单为主，属性每行填写 `名称=值`。复杂嵌套结构可切换到“粘贴 XML 片段”，提供单个完整元素及所需命名空间声明。含子元素的替换默认打开片段模式，保留完整结构供编辑。
4. 每次“应用”立即更新内存中的树和“结果预览”，支持撤销／重做。最后“保存规则组”，列表显示目标文件及修改数量。新组默认不勾选；启用后组内按编辑顺序执行，可整体上移／下移。重新编辑使用保存时的参考快照和修改记录，不依赖参考文件后来是否改动。取消不修改原规则或参考文件。

参考 XML **只用于预览**，选择它不会自动加入复制载荷。位于已识别内容根目录中的文件自动填写 `contents/相对路径`；其他位置无法可靠推断，必须填写游戏内目标路径。**原始增量包本来已有的 XML 仍随包复制，再应用 XML 编辑**。可选“修改版本日期”继续单独排除 `prop/ea3-ident.xml` 并定点修改，不受此行为影响。

无需手填 XPath：每次修改根据当时的树生成定位，优先使用同名兄弟中唯一的 `id`、`name`、`key`，否则在需要时使用同名节点序号。使用序号时界面提示依赖相同结构。修改定位属性或新增节点后，可以继续操作，后续定位使用最新值。默认和带前缀的命名空间、XPath 引号自动处理；在折叠的“高级详情”中查看实际编辑列表。

默认根据 BOM、字节序和 XML 声明识别 UTF-8、UTF-16、GBK、Shift-JIS。无声明／BOM 的文件默认 UTF-8；需要指定编码时，在高级详情中选择后点击“应用编码”。冲突、无效字符或解析失败会报错，不猜测或忽略。含子元素的节点不能直接修改文本，不能删除根元素或编辑命名空间声明；注释和处理指令保留但不可选择。DTD 和外部实体被拒绝。超过 200,000 字符的结果预览仅展示开头，完整文档仍用于编辑。旧版单动作规则保持兼容。

导出仍使用 `editXml` 和有序 `edits` 数组；本地路径、参考快照和界面记录不写入 `update`。编辑器预览仅针对参考文件，游戏中实际文件的节点匹配仍由 MediaUpdater 安装预演检查。

更新器和编辑器都会跳过完全一致的修改：相同文本／属性值、已存在且同值的新增属性、相同替换元素，以及对应位置已存在的完整插入元素。追加检查直接子元素，前后插入检查锚点对应方向的同级元素。比较忽略普通排版缩进、属性顺序和等价命名空间前缀，但保留文本、属性值、子节点顺序、注释、处理指令及有意义空白的差异。整组无需修改时，更新器不重写文件。此行为需要使用本次更新后的 MediaUpdater。

仅同名并不足以跳过；内容不同的插入仍执行，同名但值不同的新增属性仍报错。XPath 缺失或多匹配仍失败，包括删除后再次删除、替换后旧定位失效等情况；先插入再另行修改导致片段内容不同，也不属于重复的相同插入。规则列表中的修改数量表示已保存的编辑步骤，安装时会根据实际文件逐步判断是否需要执行。

执行顺序为基础 contents → launcher 和启动.exe 等编译产物 → asphyxia → 版本日期 → 已勾选附加规则。附加规则可以再次覆盖前面的结果，不会自动跳过零匹配的 XPath。此工具只进行路径、字段、XML 片段及已知载荷类型的静态检查，**不验证完整 XPath 语法、实际匹配、目标现状或安装权限**；这些由 MediaUpdater 安装预演检查。

新建模式不自动套用示例中的删除规则或插件修改。载荷中包含额外的 `update` 文件会被拒绝，因为现有更新器要求解压目录只有一份清单。

## 导入并编辑现有更新包

主窗口点击“编辑现有更新包 · 导入更新包目录”，在编辑窗口中导入**已解压目录**。可选择外套目录，整个选择范围必须只有一份 `update`。不支持 ZIP 导入，不要求原始游戏增量目录，不执行包内脚本。

导入会在后台检查 JSON、操作字段、路径、链接、大小写冲突和 SHA-256。清单非法时拒绝导入；`checksums` 缺失、格式错误、文件缺失或摘要不符时，显示详细问题，只有明确点击“继续编辑”才接受。导入失败或取消保留当前编辑会话。载荷缺失的规则可以导入修复，但启用规则的载荷修复前不能生成。

### 规则与文件

- “全部操作”按原顺序列出 `copy`、`mirror`、`delete`、`editXml`，导入操作默认启用。可编辑、停用、删除和排序；新操作默认停用。镜像操作会移除游戏目标目录中多余的文件。
- “包内文件”支持添加文件／目录、替换和移除。源路径与游戏目标路径分别相对于包目录和游戏目录；复制／镜像源须位于 `source` 内。先添加载荷，再填写对应源路径即可修复缺失引用。选择载荷时显示相关操作编号；共享载荷的修改影响所有引用，不会隐式删除操作。
- 文件树按需展开，每页显示 200 项。未引用文件、说明文件、空目录均保留。`update`、根目录 `checksums` 由工具管理。未修改载荷按原路径、原字节复制；参考 XML 不会自动加入载荷。

### 已有 XML 规则的步骤编辑

编辑 XML 组时优先从前序启用的复制／镜像操作中推导参考文件，并回放此前可确定的 XML 修改。无法推导时，请选择**该规则组执行前**的参考 XML。保存过的组在当前会话保留参考快照。

步骤列表选择一项后，节点树显示该步骤执行前的内容。“修改值 / 片段”保留原 XPath，编辑后立即重新回放；“重新绑定到所选节点”使用当前选中的元素或属性重新生成定位。树右侧的修改／新增表单在所选步骤之前插入新步骤，选择“末尾添加步骤”则追加。可删除、排序、撤销、重做，结果预览显示完整回放结果；高级详情显示 XPath 与命名空间映射。

遇到零匹配、多匹配或不支持的目标类型时，停止后续预览并标明失败步骤。可以重新绑定、调整内容／顺序或删除该步骤来修复。通过此界面保存必须全部回放成功；取消不改变原规则。尚未可视化验证的原规则在列表明确标记，允许原样导出。未改动规则保留原 XPath、编码、命名空间及完整编辑字段，编辑器元数据不导出。

回放支持 XPath 1.0，以文档节点为初始上下文；禁用 DTD、实体解析和外部资源访问。只能编辑元素或属性，不能修改文本节点、注释、处理指令、命名空间声明或删除根元素。预览针对参考快照，**实际安装仍以 C# 更新器预演为准**。

### 组件与保存

导入模式的 spice2x、KFC 插件下载、启动器编译默认全部关闭。勾选后，在 `source/components-随机标识/` 的独立子目录中准备载荷；组件操作追加在当前全部启用操作之后，不改写原包操作。启动器在预览时编译，下载在生成时执行。导入模式没有自动版本日期排除选项；修改日期使用 XML 规则，原有 `ea3-ident.xml` 载荷继续保留。

默认“另存为”，使用固定前缀和版本／自定义后缀命名；同名目录已存在时拒绝生成。也可以明确勾选“覆盖原目录”：预览显示覆盖位置和唯一同级备份位置，生成按钮变为“确认覆盖并生成”。

所有文件先在目标同卷的临时目录中准备，写入完整 `update` 和 `checksums` 后再次检查原包快照。原包发生外部修改时要求重新导入；新增／替换的本地载荷变化时要求重新选择。覆盖发布先把原目录重命名为备份，再发布暂存包；发布失败尝试恢复原目录，成功则保留备份并输出日志。目录切换期间先完成发布或恢复，再结束任务。覆盖成功后请重新导入新包继续编辑。

仅含规则、没有 `source` 的合法包也可编辑保存。会话不会写回磁盘；关闭前需生成才能保留修改。不自动压缩输出。

## 输入保护与失败处理

原始目录只读。生成前后检查输入快照；检测到变化会停止生成并要求重新预览或导入。输出与输入不得互相包含（导入模式显式覆盖除外），符号链接、目录联接、非法 Windows 路径和更新器保留路径会被拒绝。输出位置必须已存在，新建／另存为的同名输出不会被覆盖。

所有工作先在输出位置的 `.update-package-*` 暂存目录中进行，完成后发布为最终目录。取消或失败仅清理本次暂存内容；关闭窗口会先取消并等待清理。清理权限错误会显示在界面中。断电或强制结束进程可能留下暂存目录，可在确认任务已结束后手动移除。

## 开发验证

在仓库根目录运行：

```text
python -m unittest discover -s Tests -p test_update_package_tool.py -v
python -m unittest discover -s Tests -p test_update_checksums.py -v
python -m unittest discover -s Tests -p test_update_xml_editor.py -v
python -m unittest discover -s Tests -p test_update_package_import.py -v
```

设置 `UPDATE_TEST_WORKER` 为现有 C# `RegressionTests.exe` 的绝对路径后，Python 测试还会在独立临时游戏目录中验证生成包的 `verify`、`apply` 和篡改拒绝。UI 冒烟测试设置 `UPDATE_TOOL_UI_TEST=1` 后启用，需要可用的 Windows 桌面。
